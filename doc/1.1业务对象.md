# 1.1 业务对象梳理

> 本文档依据 `RMS_.md` 中的 iRMS Rule Agent 项目定位、输入输出范围和核心目标进行整理。本阶段仅完成业务建模与规则梳理，不涉及 Web 界面、数据库、接口、调度算法或状态机引擎的实现。
>
> 标记说明：文档中无法从现有需求确定的属性、状态或规则，统一标记为 **待确认**。

## 1. 梳理目标与范围

iRMS Rule Agent 面向多个 AMR 仓储项目场景，需要将半结构化业务描述转化为统一、可审查、可执行和可复用的场景模型。业务对象梳理的目标是明确系统中“有哪些对象、对象具有什么属性、对象之间如何关联、任务如何流转、规则如何约束执行”，为后续任务状态机、规则配置、确定性审查和沙箱验证提供统一基础。

本阶段覆盖以下内容：

- 场景、机器人、任务、工作站、点位、区域等核心对象；
- 货架、料箱、托盘、充电桩等仓储资源；
- 任务从创建到完成的标准流程；
- 调度、电量、优先级、任务取消和异常处理规则；
- 业务对象关系及待确认问题。

---

## 2. 核心业务对象总览

| 对象 | 主要职责 | 关键关联 |
|---|---|---|
| 场景 | 描述一个仓储项目或具体业务场景的整体配置边界 | 包含机器人、任务、工作站、点位、区域、资源和规则 |
| 机器人 | 承接并执行搬运、取放、运输、充电等任务 | 执行任务，访问点位和工作站，搬运仓储资源 |
| 机器人类型 | 定义一类机器人的通用能力和限制 | 被多个机器人实例引用，与任务类型进行能力匹配 |
| 任务 | 表示需要系统调度和执行的业务指令 | 关联任务类型、机器人、起终点、工作站和资源 |
| 任务类型 | 定义任务的标准流程、资源要求和执行条件 | 被任务实例引用，约束可执行机器人类型和状态流转 |
| 工作站 | 表示需要进行拣选、分拣、补货、退货等业务操作的作业单元 | 关联点位、任务、资源、能力和容量限制 |
| 点位 | 表示机器人可到达或执行动作的离散位置 | 归属区域，可关联工作站、货架或充电桩 |
| 区域 | 对多个点位进行业务或交通属性分组 | 包含点位，并对机器人、任务和路线施加约束 |
| 货架 | 存储商品、料箱或托盘的载体 | 位于点位，被机器人搬运或被任务引用 |
| 料箱 | 承载商品或物料的容器 | 位于货架、工作站或机器人上，被任务搬运 |
| 托盘 | 承载物料、货物或多个容器的标准载具 | 位于点位、工作站或机器人上，被任务搬运 |
| 充电桩 | 为机器人提供充电服务的资源 | 关联充电点位、适配机器人类型和占用状态 |
| 规则 | 定义调度、执行、电量、优先级、取消和异常处理条件 | 作用于场景、任务、机器人、工作站及资源 |

## 3. 场景对象

### 3.1 对象说明

场景是业务模型的顶层对象，用于描述一个仓储项目、一个仓库区域或一种业务模式下的全部对象和规则集合。一个场景可以是货架到人、料箱到人、分拣、补货、退货、工作站拣选、机器人充电或异常回流等。

### 3.2 核心属性

| 属性 | 说明 | 是否明确 |
|---|---|---|
| scene_id | 场景唯一标识 | 待确认 |
| scene_name | 场景名称 | 已明确需要 |
| scene_type | 场景类型，如货架到人、料箱到人、分拣、补货、退货、充电等 | 已明确范围，具体枚举待确认 |
| description | 场景业务说明 | 已明确需要 |
| version | 场景模型或规则版本 | 待确认 |
| enabled | 场景是否启用 | 待确认 |
| robot_types | 场景允许使用的机器人类型 | 已明确需要 |
| task_types | 场景支持的任务类型 | 已明确需要 |
| stations | 场景中的工作站集合 | 已明确需要 |
| points | 场景中的点位集合 | 已明确需要 |
| areas | 场景中的区域集合 | 已明确需要 |
| resources | 场景中的货架、料箱、托盘、充电桩等资源 | 已明确需要 |
| rule_set | 场景使用的规则集合 | 已明确需要 |
| task_templates | 场景可复用的任务模板 | 已明确需要 |

### 3.3 状态

| 状态 | 说明 |
|---|---|
| 草稿 | 场景仍在编辑，尚未完成规则审查 |
| 待审查 | 场景对象和规则已生成，等待确定性审查 |
| 审查失败 | 存在状态不可达、规则冲突或异常分支缺失等问题 |
| 可验证 | 已通过静态审查，可以进入沙箱验证 |
| 验证失败 | 沙箱执行未能从任务创建正常流转到完成 |
| 可用 | 已通过审查和沙箱验证 |
| 已停用 | 不再用于生成或验证配置 |

> 上述场景状态用于支撑 Rule Agent 的生成、审查和验证过程，具体状态名称及是否需要持久化均为 **待确认**。

### 3.4 对象关系

- 一个场景包含多个机器人类型、机器人、任务类型、工作站、点位和区域。
- 一个场景包含多个仓储资源实例。
- 一个场景绑定一套或多套业务规则。
- 一个场景可以由某个历史场景模板复制或派生，具体复用方式待确认。

## 4. 机器人类型及机器人对象

## 4.1 机器人类型

### 对象说明

机器人类型用于描述同一类 AMR 的通用能力、物理限制和业务适配范围。调度规则应先判断机器人类型是否具备执行指定任务的能力，再判断具体机器人实例是否可用。

### 核心属性

| 属性 | 说明 | 是否明确 |
|---|---|---|
| robot_type_id | 机器人类型唯一标识 | 待确认 |
| type_name | 类型名称 | 已明确需要 |
| capability_codes | 可执行能力集合，如搬运货架、搬运料箱、搬运托盘、顶升、牵引等 | 能力范围待确认 |
| supported_task_types | 可执行的任务类型集合 | 已明确需要 |
| supported_resource_types | 可搬运或操作的资源类型 | 待确认 |
| max_load | 最大负载 | 待确认 |
| size | 长、宽、高等尺寸 | 待确认 |
| speed_limit | 最大运行速度 | 待确认 |
| battery_capacity | 电池容量 | 待确认 |
| charge_compatibility | 可使用的充电桩类型 | 待确认 |
| allowed_area_types | 可进入的区域类型 | 待确认 |
| docking_modes | 支持的对接方式 | 待确认 |

### 状态

机器人类型一般作为静态配置对象，可采用“启用、停用”两种状态，是否需要版本状态待确认。

### 关系

- 一个机器人类型可以对应多个机器人实例。
- 一个机器人类型可以支持多个任务类型。
- 一个任务类型可以允许一个或多个机器人类型执行。
- 一个机器人类型可以适配一个或多个充电桩类型。

## 4.2 机器人实例

### 对象说明

机器人是实际参与任务分配与执行的设备实例。机器人实例继承机器人类型的通用能力，同时维护自身位置、电量、运行状态和当前任务等动态信息。

### 核心属性

| 属性 | 说明 | 是否明确 |
|---|---|---|
| robot_id | 机器人唯一标识 | 已明确需要，格式待确认 |
| robot_name | 机器人名称或编号 | 待确认 |
| robot_type_id | 所属机器人类型 | 已明确需要 |
| current_point_id | 当前所在点位 | 已明确需要 |
| current_area_id | 当前所在区域 | 可由点位推导，是否冗余保存待确认 |
| battery_level | 当前电量 | 已明确需要 |
| operational_status | 当前运行状态 | 已明确需要 |
| current_task_id | 当前执行任务 | 已明确需要 |
| load_status | 当前是否载货及载荷信息 | 待确认 |
| carried_resource_id | 当前搬运的货架、料箱或托盘 | 待确认 |
| fault_code | 故障码 | 待确认 |
| online_status | 在线或离线状态 | 待确认 |
| last_heartbeat_time | 最近心跳时间 | 待确认 |

### 状态

| 状态 | 说明 |
|---|---|
| 离线 | 无法参与任务分配 |
| 空闲 | 在线且没有执行任务，可参与接单 |
| 已分配 | 已绑定任务，尚未开始移动或执行 |
| 执行中 | 正在执行任务流程 |
| 等待中 | 因工作站、资源、交通或前置条件未满足而等待 |
| 充电中 | 正在充电 |
| 低电量 | 电量低于任务接单或续航阈值 |
| 故障 | 设备异常，不能正常执行任务 |
| 人工接管 | 由人工处理，不参与自动调度 |
| 停用 | 被管理员禁用 |

> 是否需要区分“前往充电”“充电完成”“恢复执行”等更细状态，待确认。

### 关系

- 每个机器人实例归属于一个机器人类型。
- 一个机器人同一时刻是否只能执行一个主任务，待确认。
- 机器人可搬运一个或多个资源，具体承载数量由机器人类型决定。
- 机器人通过点位和区域运行，并受区域通行约束。
- 机器人可以在充电桩执行充电任务。

## 5. 任务类型及任务对象

## 5.1 任务类型

### 对象说明

任务类型定义一类业务任务的标准执行流程、所需能力、资源类型、起终点条件、状态流转和异常分支，是生成任务状态机和规则配置的核心对象。

### 核心属性

| 属性 | 说明 | 是否明确 |
|---|---|---|
| task_type_id | 任务类型唯一标识 | 待确认 |
| task_type_name | 任务类型名称 | 已明确需要 |
| business_category | 业务类别，如货架到人、料箱到人、分拣、补货、退货、充电、异常回流等 | 已明确范围 |
| required_capabilities | 执行该任务需要的机器人能力 | 已明确需要 |
| source_object_type | 起点可接受的对象类型，如点位、货架、工作站 | 待确认 |
| target_object_type | 终点可接受的对象类型 | 待确认 |
| resource_type | 任务操作的资源类型 | 待确认 |
| standard_flow | 标准状态流转流程 | 已明确需要 |
| cancel_policy | 任务取消规则 | 已明确需要，具体内容待确认 |
| exception_policy | 异常处理规则 | 已明确需要，具体内容待确认 |
| default_priority | 默认优先级 | 待确认 |
| timeout | 默认超时时间 | 待确认 |

### 状态

任务类型属于配置对象，建议至少包含“草稿、启用、停用”状态，具体状态待确认。

### 关系

- 一个任务类型可以创建多个任务实例。
- 一个任务类型关联一个标准流程和若干异常分支。
- 一个任务类型允许一个或多个机器人类型执行。
- 一个任务类型可以关联一种或多种资源类型、工作站类型及区域规则。

## 5.2 任务实例

### 对象说明

任务实例表示一次具体的仓储业务指令，是调度、执行、状态流转、规则触发和沙箱验证的主要载体。

### 核心属性

| 属性 | 说明 | 是否明确 |
|---|---|---|
| task_id | 任务唯一标识 | 已明确需要，格式待确认 |
| task_type_id | 所属任务类型 | 已明确需要 |
| scene_id | 所属场景 | 已明确需要 |
| source_point_id | 起始点位 | 已明确需要，部分任务是否可为空待确认 |
| target_point_id | 目标点位 | 已明确需要，部分任务是否可动态确定待确认 |
| source_station_id | 起始工作站 | 待确认 |
| target_station_id | 目标工作站 | 待确认 |
| resource_id | 关联货架、料箱或托盘 | 待确认 |
| assigned_robot_id | 已分配机器人 | 已明确需要 |
| priority | 当前优先级 | 已明确需要 |
| status | 当前任务状态 | 已明确需要 |
| created_time | 创建时间 | 待确认 |
| assigned_time | 分配时间 | 待确认 |
| started_time | 开始执行时间 | 待确认 |
| completed_time | 完成时间 | 待确认 |
| deadline | 截止时间或时间窗 | 待确认 |
| retry_count | 当前重试次数 | 待确认 |
| parent_task_id | 父任务或来源任务 | 待确认 |
| cancel_reason | 取消原因 | 待确认 |
| exception_code | 当前异常代码 | 待确认 |
| context | 任务执行过程中需要传递的业务上下文 | 待确认 |

### 标准状态

| 状态 | 说明 | 是否为必需状态 |
|---|---|---|
| 已创建 | 任务数据已经生成 | 是 |
| 待校验 | 等待业务完整性和规则校验 | 待确认 |
| 待分配 | 满足创建条件，等待分配机器人 | 是 |
| 已分配 | 已绑定机器人 | 是 |
| 执行中 | 机器人已经开始执行 | 是 |
| 等待中 | 因资源、工作站或业务条件暂时不能继续 | 待确认 |
| 已完成 | 所有标准步骤执行成功 | 是 |
| 取消中 | 已发起取消，但仍需处理机器人或资源状态 | 待确认 |
| 已取消 | 任务终止且取消处理结束 | 是 |
| 异常 | 任务执行过程中发生异常 | 是 |
| 重试中 | 异常后重新执行当前步骤或任务 | 待确认 |
| 人工处理 | 自动规则无法完成处理，转人工 | 待确认 |
| 失败 | 达到终止条件且无法继续执行 | 待确认 |

> 不同任务类型可能具有更细的内部步骤状态。最终状态名称、状态码和可达关系应在后续状态机设计阶段确定。

### 关系

- 每个任务实例归属于一个任务类型和一个场景。
- 一个任务在执行时关联零个或一个机器人；是否允许多机器人协同任务待确认。
- 一个任务可以关联工作站、点位、区域及仓储资源。
- 一个任务可以由上游系统、人工、规则引擎或其他任务触发，来源类型待确认。
- 一个任务可能拆分为多个子任务，是否支持任务编排待确认。

## 6. 工作站对象

### 6.1 对象说明

工作站是执行拣选、分拣、补货、退货、交接等人工或自动业务操作的作业单元。工作站既是任务流程中的业务节点，也是具有容量、能力和占用约束的调度资源。

### 6.2 核心属性

| 属性 | 说明 | 是否明确 |
|---|---|---|
| station_id | 工作站唯一标识 | 已明确需要，格式待确认 |
| station_name | 工作站名称 | 待确认 |
| station_type | 工作站类型，如拣选、分拣、补货、退货等 | 已明确范围，枚举待确认 |
| capability_codes | 工作站支持的业务能力 | 已明确需要 |
| point_ids | 工作站关联的到达、等待、操作或离开点位 | 已明确需要，点位角色待确认 |
| capacity | 工作站最大同时处理数量 | 已明确需要，单位待确认 |
| queue_capacity | 等待队列容量 | 待确认 |
| supported_task_types | 支持处理的任务类型 | 已明确需要 |
| supported_resource_types | 支持处理的资源类型 | 待确认 |
| operating_status | 当前运行状态 | 已明确需要 |
| opening_hours | 可用时间范围 | 待确认 |
| processing_time | 标准处理时间 | 待确认 |
| current_load | 当前占用或排队数量 | 待确认 |

### 6.3 状态

| 状态 | 说明 |
|---|---|
| 空闲 | 可立即接收任务或机器人 |
| 忙碌 | 正在处理任务，但是否可继续排队由容量决定 |
| 已满 | 当前容量或队列已达到上限 |
| 暂停 | 暂时停止接收新任务 |
| 故障 | 工作站异常，不能继续执行任务 |
| 离线 | 系统无法与工作站正常通信 |
| 停用 | 配置层面被禁用 |

### 6.4 关系

- 一个工作站可以关联一个或多个点位。
- 一个工作站可以支持多个任务类型。
- 一个任务可以在一个或多个工作站完成部分业务步骤，具体是否支持多工作站流程待确认。
- 工作站可以接收机器人送达的货架、料箱或托盘。
- 工作站状态会影响任务分配、目标选择和任务等待。

## 7. 点位与区域对象

## 7.1 点位

### 对象说明

点位是仓库地图中可被业务对象引用的离散位置，用于表示机器人当前位置、任务起终点、工作站对接位置、资源存储位置和充电位置等。

### 核心属性

| 属性 | 说明 | 是否明确 |
|---|---|---|
| point_id | 点位唯一标识 | 已明确需要 |
| point_name | 点位名称 | 待确认 |
| point_type | 点位类型，如普通、取货、放货、等待、工作站、货架、充电等 | 已明确范围，枚举待确认 |
| coordinate | 地图坐标 | 待确认 |
| area_id | 所属区域 | 已明确需要 |
| enabled | 是否启用 | 待确认 |
| occupancy_status | 当前占用状态 | 待确认 |
| max_occupancy | 最大占用数量 | 待确认 |
| allowed_robot_types | 可进入的机器人类型 | 待确认 |
| bound_resource_id | 固定关联资源，如货架位或充电桩 | 待确认 |
| direction_constraint | 进入、离开或对接方向限制 | 待确认 |

### 状态

| 状态 | 说明 |
|---|---|
| 可用 | 可作为任务或机器人目标点 |
| 被占用 | 已被机器人或资源占用 |
| 已预订 | 已被某个任务或机器人预占 |
| 禁用 | 暂时或永久不可用 |
| 阻塞 | 因异常或交通原因暂时无法到达 |

### 关系

- 一个点位归属于一个区域。
- 一个点位可关联工作站、货架位或充电桩。
- 任务可以引用起始点位、目标点位及中间业务点位。
- 机器人在任意时刻应位于某个点位或点位间路径，位置表示方式待确认。

## 10. 任务标准流程

## 10.1 通用主流程

```text
任务创建
  ↓
基础信息校验
  ↓
业务条件与资源校验
  ↓
进入待分配状态
  ↓
筛选候选机器人
  ↓
执行调度约束校验
  ↓
选择并绑定机器人
  ↓
机器人接收任务
  ↓
执行任务标准步骤
  ↓
到达目标业务节点
  ↓
完成取货、放货、交接、拣选或充电等业务动作
  ↓
校验任务完成条件
  ↓
释放机器人、工作站、点位及仓储资源占用
  ↓
任务完成
```

## 10.2 分阶段说明

| 阶段 | 主要动作 | 进入条件 | 正常输出 | 可能异常 |
|---|---|---|---|---|
| 任务创建 | 接收外部或内部任务请求，生成任务实例 | 请求包含基本任务信息 | 已创建任务 | 参数缺失、任务类型不存在、重复任务 |
| 基础校验 | 校验场景、任务类型、起终点及资源引用 | 任务已创建 | 校验通过 | 对象不存在、对象停用、字段不完整 |
| 业务校验 | 校验工作站能力、资源状态、区域限制等 | 基础校验通过 | 任务可进入待分配 | 资源不可用、工作站不支持、区域不可进入 |
| 待分配 | 任务进入调度队列 | 校验通过且未取消 | 候选机器人集合 | 无可用机器人、低电量、机器人能力不匹配 |
| 任务分配 | 根据规则选择机器人并建立绑定 | 至少存在一个合格候选机器人 | 任务已分配 | 并发抢占、机器人状态变化、资源被占用 |
| 执行准备 | 机器人确认任务并锁定相关资源 | 机器人在线且可接单 | 开始执行 | 接单失败、资源锁定失败、机器人离线 |
| 前往起点 | 机器人前往取货点、资源点或工作站 | 路径及区域可通行 | 到达起点 | 点位阻塞、区域关闭、机器人故障 |
| 起点作业 | 取货、顶升、装载或业务确认 | 机器人到达且资源有效 | 资源与机器人绑定 | 资源不存在、资源被占、动作失败 |
| 前往终点 | 搬运资源前往目标点或工作站 | 起点作业完成 | 到达终点 | 目标不可用、工作站已满、交通异常 |
| 终点作业 | 放货、卸载、交接、拣选或业务确认 | 到达终点且目标允许操作 | 业务动作完成 | 对接失败、工作站故障、人工操作超时 |
| 完成校验 | 校验所有必要步骤和资源状态 | 标准流程步骤完成 | 任务完成 | 状态不一致、资源未释放、完成条件不足 |
| 资源释放 | 释放机器人、点位、工作站和资源锁 | 任务完成、取消或失败 | 对象恢复可调度状态 | 释放失败、状态冲突 |

## 10.3 流程设计原则

1. 每个任务类型必须具有明确的开始状态和至少一个终止状态。
2. 正常流程必须能够从“已创建”到达“已完成”。
3. 每个关键步骤应定义进入条件、执行动作、成功条件和失败分支。
4. 异常发生后必须明确重试、等待、取消、失败或转人工中的一种处理结果。
5. 任务状态变化应与机器人、资源、工作站和点位状态保持一致。
6. 任务取消或失败后，必须具有资源释放或状态恢复步骤。
7. 具体任务类型的详细流程由后续场景输入确定，当前不自行扩展复杂业务步骤。

## 11. 调度约束

调度约束用于判断某个任务是否可以分配给某个机器人，以及某个机器人是否可以在当前时间执行该任务。

| 约束类别 | 规则说明 | 未明确内容 |
|---|---|---|
| 状态约束 | 机器人必须在线、启用且处于可接单状态 | 等待中或充电中的机器人是否可接单待确认 |
| 能力约束 | 机器人类型必须满足任务所需能力 | 能力编码及匹配方式待确认 |
| 任务类型约束 | 机器人类型必须被任务类型允许 | 是否支持动态覆盖待确认 |
| 负载约束 | 资源重量、尺寸和承载方式不能超过机器人能力 | 具体阈值待确认 |
| 电量约束 | 当前电量必须满足接单阈值和预计执行能耗要求 | 阈值和估算方式待确认 |
| 点位约束 | 机器人必须能够访问任务起点和终点 | 点位可达性的判定来源待确认 |
| 区域约束 | 机器人类型和任务类型必须允许进入相关区域 | 区域规则优先级待确认 |
| 工作站约束 | 工作站必须支持任务类型且未停用 | 忙碌、已满时是否允许提前分配待确认 |
| 资源约束 | 任务关联的货架、料箱或托盘必须可用且未被冲突占用 | 资源锁定机制待确认 |
| 并发约束 | 同一机器人、点位、工作站或资源不能产生不允许的并发占用 | 各对象并发容量待确认 |
| 时间约束 | 任务可能受到创建时间、截止时间、工作站开放时间等限制 | 时间窗规则待确认 |
| 任务互斥 | 存在冲突的任务不能同时执行 | 互斥条件待确认 |
| 前置任务约束 | 部分任务必须在前置任务完成后执行 | 是否支持依赖链待确认 |

### 11.1 建议的约束判定顺序

```text
对象有效性
→ 机器人在线与运行状态
→ 机器人能力匹配
→ 资源类型与负载匹配
→ 点位及区域访问权限
→ 工作站能力与容量
→ 电量与续航条件
→ 资源占用与并发冲突
→ 时间、优先级及其他业务约束
```

该顺序仅用于业务梳理，后续实现时是否采用短路校验、规则优先级或统一规则引擎，待确认。

## 12. 电量策略

### 12.1 电量区间

| 区间 | 建议业务含义 | 阈值 |
|---|---|---|
| 正常电量 | 可以正常接收和执行任务 | 待确认 |
| 关注电量 | 可以完成短任务，但需要评估任务结束后的剩余电量 | 待确认 |
| 低电量 | 原则上不再接收普通任务，优先执行充电任务 | 待确认 |
| 紧急电量 | 应停止新任务分配并尽快前往充电 | 待确认 |
| 保护电量 | 可能需要原地停止、人工处理或执行安全策略 | 待确认 |

### 12.2 基本规则

1. 机器人接收任务前，应检查当前电量是否满足最低接单阈值。
2. 条件允许时，应检查机器人是否具备完成任务并到达可用充电桩的预计电量。
3. 低电量机器人原则上不接收普通搬运任务，应生成或触发充电任务。
4. 紧急电量下，是否允许中断当前任务、先放置资源或直接前往充电，待确认。
5. 充电任务的优先级原则上应高于普通低优先级任务，具体比较规则待确认。
6. 机器人达到停止充电阈值后，可结束充电并恢复空闲状态。
7. 是否支持机会充电、排队充电、充电桩预约及充电任务抢占，待确认。

## 13. 优先级策略

### 13.1 优先级来源

任务优先级可能来自以下信息：

- 任务类型默认优先级；
- 上游系统显式指定优先级；
- 创建时间或等待时长；
- 任务截止时间或超时风险；
- 工作站缺料、拥堵或业务紧急程度；
- 充电、异常恢复等系统任务类别；
- 人工调整；
- 任务依赖关系。

其中具体使用哪些来源以及权重如何定义，均为 **待确认**。

### 13.2 基本规则

1. 优先级用于决定多个可执行任务之间的先后顺序，不应绕过机器人能力、安全及资源约束。
2. 高优先级任务可以优先获得空闲机器人和可用资源。
3. 是否允许高优先级任务抢占已分配或执行中的低优先级任务，待确认。
4. 为避免普通任务长期得不到执行，可考虑基于等待时间提升优先级，是否启用待确认。
5. 相同优先级下的排序规则可采用创建时间、截止时间或距离等条件，具体待确认。
6. 人工调整优先级后是否允许恢复默认值以及是否需要审计记录，待确认。

## 14. 任务取消策略

### 14.1 按任务阶段处理

| 任务阶段 | 取消处理原则 | 待确认内容 |
|---|---|---|
| 已创建/待校验 | 可直接取消，不涉及机器人和资源恢复 | 是否保留审查记录待确认 |
| 待分配 | 从调度队列移除并释放预占资源 | 是否存在预占资源待确认 |
| 已分配未执行 | 解除机器人绑定并释放预订对象 | 机器人是否需要确认取消待确认 |
| 前往起点 | 停止当前任务并重新调度机器人 | 是否允许立即中止待确认 |
| 已取货/搬运中 | 不能简单终止，必须确定资源安置位置 | 返还起点、送至缓冲区或继续到终点待确认 |
| 工作站处理中 | 应与工作站业务状态协调后取消 | 人工操作已开始时是否允许取消待确认 |
| 已完成 | 原则上不能取消，可通过补偿任务处理 | 补偿任务机制待确认 |
| 异常/重试中 | 可根据异常处理进度取消，并执行资源恢复 | 异常与取消规则优先级待确认 |

### 14.2 基本规则

1. 取消请求必须记录取消来源、原因和时间。
2. 取消前应检查当前任务状态是否允许取消。
3. 取消任务必须同步处理机器人绑定、资源锁定、工作站占用和点位预订。
4. 已经搬运资源的任务取消时，必须明确资源最终去向。
5. 任务取消后必须进入明确终态，不能长期停留在“取消中”。
6. 取消失败时，应进入异常处理或人工处理分支。
7. 是否支持批量取消、级联取消和父子任务联动取消，待确认。

## 15. 异常分支

## 15.1 异常分类

| 异常类别 | 典型异常 | 默认处理方向 |
|---|---|---|
| 输入异常 | 字段缺失、对象不存在、任务重复 | 拒绝创建或进入待修正状态 |
| 机器人异常 | 离线、故障、无法接单、动作失败 | 重试、重新分配、转人工或失败 |
| 电量异常 | 电量不足、充电失败 | 触发充电、换机器人或转人工 |
| 点位异常 | 点位被占、阻塞或禁用 | 等待、换点位、重新规划或失败 |
| 区域异常 | 区域封闭、容量已满、权限不满足 | 等待、换区域或重新分配 |
| 工作站异常 | 工作站故障、已满、暂停或处理超时 | 等待、切换工作站或转人工 |
| 资源异常 | 货架、料箱或托盘不存在、被占用、状态不一致 | 重新校验、换资源或转人工 |
| 任务异常 | 状态流转非法、超时、重试次数超限 | 重试、取消、失败或转人工 |
| 规则异常 | 规则冲突、无规则匹配、目标状态不可达 | 阻止发布或进入审查失败 |
| 通信异常 | 与机器人、工作站或上游系统通信失败 | 重试、等待、降级或转人工 |

## 15.2 通用异常处理流程

```text
检测异常
  ↓
记录异常类型、对象、步骤和上下文
  ↓
判断异常是否可自动恢复
  ├─ 可恢复：等待 / 重试 / 重新分配 / 切换资源
  │          ↓
  │       恢复任务执行
  └─ 不可恢复：执行安全停止和资源保护
             ↓
          转人工 / 取消 / 失败
             ↓
          释放或恢复相关对象状态
```

## 15.3 异常处理原则

1. 每个关键流程步骤至少应定义一个失败出口。
2. 异常分支必须有终止条件，避免无限重试或永久等待。
3. 重试规则至少应包含最大次数、间隔和失败后的处理方式，具体数值待确认。
4. 重新分配机器人前，应确认原机器人已解除任务及资源绑定。
5. 机器人故障且携带资源时，应优先保证资源状态和现场安全，具体流程待确认。
6. 工作站或目标点不可用时，可等待或切换候选目标，是否允许自动切换待确认。
7. 任何异常处理结束后，任务、机器人、资源和工作站状态必须保持一致。
8. 无法自动处理的异常应进入人工处理，并保存完整执行轨迹和规则触发记录。

## 16. 规则对象建议

为了支持后续规则生成、审查和沙箱验证，可将规则作为独立业务对象进行描述。本阶段只定义业务含义，不实现规则引擎。

| 属性 | 说明 | 是否明确 |
|---|---|---|
| rule_id | 规则唯一标识 | 待确认 |
| rule_name | 规则名称 | 已明确需要 |
| rule_type | 调度、电量、工作站、区域、优先级、取消或异常规则 | 已明确范围 |
| scope | 规则作用场景或对象范围 | 待确认 |
| condition | 规则触发条件 | 已明确需要 |
| action | 条件满足后执行的业务动作 | 已明确需要 |
| priority | 多条规则同时满足时的执行顺序 | 待确认 |
| enabled | 是否启用 | 待确认 |
| version | 规则版本 | 待确认 |
| description | 规则业务说明 | 已明确需要 |

规则之间至少应检查以下问题：

- 条件相同但动作互斥；
- 多条规则形成循环触发；
- 必需场景没有规则覆盖；
- 规则指向不存在或不可达的状态；
- 取消、异常和正常流转同时生效；
- 高优先级规则绕过安全或能力约束；
- 规则执行后对象状态不一致。
