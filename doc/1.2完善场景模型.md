# 1.2 完善场景模型

本阶段依据 `doc/1.1业务对象.md` 的业务对象、核心属性、状态、对象关系、任务流程和业务规则进行建模，并使用 `doc/RMS_Agent说明.md` 核对项目目标与需求边界。

本阶段只实现 Pydantic v2 数据模型及校验，不实现数据库、接口、Web 页面、任务调度算法、状态机执行器和规则引擎。

## 模型清单

已在 `src/irms/models/scenario.py` 中实现以下模型：

- `BasicInfo`：场景基本信息
- `RobotType`：机器人类型
- `TaskType`：任务类型
- `Workstation`：工作站
- `Location`：点位与区域
- `Resource`：货架、料箱、托盘、充电桩
- `TaskFlow`：任务标准流程
- `DispatchConstraint`：调度约束
- `BatteryPolicy`：电量策略
- `PriorityPolicy`：优先级策略
- `CancellationPolicy`：任务取消策略
- `ExceptionBranch`：异常分支
- `Assumption`：建模假设
- `ManualConfirmation`：待人工确认事项
- `ScenarioModel`：组合场景模型

## 建模原则

- 需求已明确的字段按 1.1 文档实现。
- 需求未明确但模型需要承载的字段设为可选，并在 `description` 中标记“待确认”。
- 待确认业务参数写入 `manual_confirmations`，不自行填写默认业务值。
- 类型、状态和策略类别等关键字段使用枚举。
- 电量、容量、数量、优先级等数值字段设置范围校验。
- 本阶段不扩展复杂调度规则，不实现规则执行。

## 校验能力

`ScenarioModel` 已实现以下确定性校验：

- `robot_types`、`task_types`、`workstations`、`locations`、`resources`、`task_flows`、`exception_branches`、`dispatch_constraints`、`assumptions`、`manual_confirmations` 的 ID 唯一性。
- 机器人类型引用的任务类型必须存在。
- 任务类型引用的机器人类型、标准流程、工作站、点位/区域、异常分支、取消策略必须存在。
- 工作站引用的点位和任务类型必须存在。
- 点位引用的区域、机器人类型、任务类型和绑定资源必须存在。
- 资源引用的点位/工作站和兼容机器人类型必须存在。
- 任务流程引用的任务类型、工作站、点位/区域和异常分支必须存在。
- 调度约束引用的任务类型和机器人类型必须存在。

## 示例与 Schema

最小可运行场景示例：

- `examples/shelf_to_person.json`

JSON Schema 导出方式：

```bash
python scripts/export_scenario_schema.py examples/scenario_schema.json
```

也可以在代码中直接调用：

```python
from irms.models.scenario import scenario_json_schema

schema = scenario_json_schema()
```
